# Decoder Data Flow

D03 完了。公開レポートの構造を維持し、通常のデコード経路での中間レポート生成をなくした。

## Boundaries

| 段階 | 入力 | 確定する情報 | 次に渡すもの |
|---|---|---|---|
| NMEA / HEX / UBX / net | 電文と任意の受信時刻 | 正規化した時刻、本体、衛星情報、NMEA 表現 | 共通デコーダへの明示的な引数 |
| 共通解析 | `Frame` | CRC の検証、preamble、message type | `Message` |
| DCR 共通解析 | `Message` | バージョン、分類、発表時刻、情報種別 | `Jma` |
| DCR 各カテゴリ | `Jma` | 各災害のフィールド | 最終レポート |
| DCX | `Message` | CAMF、種別、存在する警報フィールド | 最終レポート |

`Frame`・`Message`・`Jma` は内部の frozen dataclass。内容はバイト列・文字列・数値・日時で、
公開レポートや可変の解析結果を保持しない。入力形式の処理で決めた受信時刻を下流まで渡す。
内部コンストラクタの注釈は静的検査用であり、dataclass が実行時に型を検証するわけではない。
入力電文の検証は引き続き各デコーダが行う。

境界ごとの `params()` は、それぞれ `FrameParams`・`MessageParams`・`JmaParams` という
TypedDict を返す。段階が増す際の引数展開と、既存レポートのキーワード引数への接続を
型検査するためのもの。汎用の `asdict()` や `dict[str, Any]` に戻してデコーダ間を渡さない。

最初の一境界だけでは明示的な引数が最小だった。下流の共通項目を含めて整理した結果、
内部データ型と型付きのキーワード表現を採用した。二つの表現のフィールド宣言は必要になるが、
任意の辞書で渡していた必須値と各段階の違いを検査できる。

## Report Compatibility

公開レポートの実装は変更しない。コンストラクタ、変更可能な属性、継承、比較・ハッシュ、
日本語表示、辞書の深いコピー、南海トラフ情報の共有状態を維持する。
全レポートへの dataclass 導入、不変化、表示の分離は D03 に含めない。

DCR の最終生成は、`JmaParams` とカテゴリ固有の明示的な引数を渡す。
DCX の最終生成だけは既存のキーワード引数 API に合わせた辞書変換を残す。
DCX は未設定属性が `None` と読めても、インスタンス辞書には存在しないことがある。
全項目を既定値付きの dataclass にまとめると、この出力契約が変わる。
そのため、型付きの共通情報と実際に解析した項目だけを最終コンストラクタへ渡す。
内部 context はレポートに混入させない。

この最終互換変換には `Any` が残る。D03 完了は、公開レポートの任意のキーワード引数まで
全面的に型安全になったことを意味しない。デコーダ間の必須入力を型で表現し、
中間レポートの生成・コピーをなくしたことが完了条件である。

旧 `decoders.base.Base` の schema / set_params は直接サブクラス化するコードと既存テストの
ために残すが、組み込みのデコーダ経路では使わない。入力形式のデコーダは電文と受信時刻を、
下流のデコーダは対応する context を受け取る。内部デコーダの以前の任意 kwargs による
生成・変更まで互換性を保証するものではない。
例外の文章と、電文・時刻・解析途中の診断用属性は維持する。

## Verification

- 全 DCR カテゴリ、NULL DCX、警報 DCX × 4入力形式で、最終レポート1個だけを生成する。
  このテストは変更前の実装で失敗することも確認する。
- 現在時刻を読むのは入力段階の1回だけ。指定時刻、UTC 正規化、年月日の補完は既存テストでも確認。
- 例外に元の電文・NMEA・時刻・解析済みの属性が残ることを確認。
- 既存ログの文章・属性のゴールデン比較、DCX の欠落キー、深いコピー、等価性・ハッシュ、
  南海トラフの組み立てを含む既存テストが成功。ゴールデンファイルは更新しない。
- 共通入力と下流 context の不足・型違い・段階違いの10誤用を、mypy と Pyright の両方で検出する。
